# Glossary

**Accelerometer** — sensor measuring device movement/rotation rate; enables orientation detection and tilt-based interactions (Ch 3)

**Autocapitalize / autocorrect** — HTML input attributes controlling automatic text casing/correction; toggle per field semantics, degrade harmlessly if unsupported (Ch 6)

**Breakpoint** — a conditional width threshold at which a responsive design applies a different set of layout rules and media assets, typically via CSS3 media queries (Ch 7)

**Check In/Status** — mobile usage mode: recurring glances at something that keeps changing/updating (Ch 4)

**Contextual navigation** — navigation or actions scoped to the current content/task rather than global (e.g., Gmail's per-message action menu) (Ch 4)

**Content over navigation** — mobile IA principle: lead with content/task, minimize navigation chrome in the initial view (Ch 4)

**Cover the hover** — the practice of explicitly redesigning any `:hover`-dependent desktop interaction for touch devices, since there is no hover state without a pointer (Ch 5)

**Device experience** — a device class (connected TV, desktop, tablet, smartphone, feature phone) defined by its characteristic user posture, primary input method, and display size (Ch 7)

**Device orientation** — a device's rotational position (portrait/landscape, tilt angle), detected via accelerometer/gyroscope (Ch 3)

**Edit/Create** — mobile usage mode: an urgent task that must be completed now and can't wait (Ch 4)

**Explore/Play** — mobile usage mode: idle-time browsing with no urgent goal (Ch 4)

**Feature phone** — a basic mobile device without a modern smartphone-class browser/app ecosystem (Ch 1)

**Fluid layout** — a layout whose elements expand/contract to fill available screen space, without discrete breakpoints (Ch 7)

**Go small by going big** — the rule that mobile touch targets must be sized larger than their desktop/proportionally-shrunk equivalents, because fingers are less precise than a mouse pointer (Ch 5)

**In-context input** — an input layout scenario: a single inline field for lightweight, frequent contributions (e.g., commenting) without navigating away (Ch 6)

**Input mask** — a UI technique constraining allowed characters and revealing an input's expected format up front (e.g., phone number formatting) (Ch 6)

**Labels-in-field** — form labels placed inside the input itself rather than above/beside it; native-common, requires custom implementation on the web, risks label/answer confusion (Ch 6)

**Location detection** — determining device position via GPS, WiFi beacon, cell tower triangulation, or IP lookup, each with distinct accuracy/speed/battery trade-offs (Ch 3)

**Lookup/Find** — mobile usage mode: an urgent need for an answer, often location-relevant (Ch 4)

**Meta viewport tag** — `<meta name="viewport" content="width=device-width">`; tells the mobile browser to use the device's actual width as the layout viewport (Ch 7)

**Mobile first** — the book's core framework: design and build the mobile experience before the desktop one, letting mobile's constraints drive prioritization (Ch 1)

**Mobile web** — the browser-based experience on a mobile device, as opposed to a platform-specific native application (Ch 1)

**Native application** — platform-specific software with direct access to system/hardware resources, unavailable to browser-based experiences (Ch 1)

**Natural User Interface (NUI)** — an interaction philosophy making content itself the interface (e.g., pinch-to-zoom on a photo) rather than routing actions through chrome (windows, icons, menus, pointers) (Ch 5)

**Needs first, hardware second** — the principle that device capabilities should be adopted to serve an identified user need, never as novelty for its own sake (Ch 3)

**Non-linear input** — an input layout scenario: a list of current values with tap-to-edit access to individual fields, for rarely-edited data (e.g., profile editing) (Ch 6)

**"One eyeball, one thumb"** — mental model for mobile usage: users typically have partial attention and one hand free, holding the device with the other (Ch 2)

**Pixel density (ppi)** — the number of physical pixels per inch of screen; devices can share a CSS device-width while differing significantly in ppi (Ch 7)

**Reduction** — the book's closing layout principle: minimize functionality/complexity as the most reliable response to growing device/context variety (Ch 7)

**Responsive web design** — fluid layouts + flexible media + CSS3 media queries (+ optional JS) applied at breakpoints to adapt layout significantly across device widths (Ch 7)

**Sequential input** — an input layout scenario: a group of related questions that must be answered together to complete a task (e.g., checkout) (Ch 6)

**Smart defaults** — pre-filled input values reflecting the majority-case answer, reducing required user effort (Ch 6)

**Touch gesture** — a standardized touch interaction (tap, double tap, drag, swipe, pinch, spread, press, rotate, etc.); mobile web safely supports a narrower subset (tap, drag, swipe) (Ch 5)

**Touch target** — the tappable hit-area of an interactive element, sized per physical dimensions (points/mm) rather than raw pixels to normalize across screen densities (Ch 5)
